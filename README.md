# Что на самом деле работает в RAG?

Учебный проект по курсу LLM (Университет Иннополис, 2026). Я собрала RAG-пайплайн на русскоязычном корпусе научных статей о психологии близких отношений и проверила четыре гипотезы. В каждой меняется одно звено пайплайна, остальные остаются прежними.

**Пайплайн:** корпус (10 статей) → chunking → эмбеддинги `multilingual-e5-small` → Chroma (cosine) → поиск → генерация `Qwen2.5-0.5B-Instruct`

**Оценка:** 10 вопросов, релевантные фрагменты размечены вручную, метрика Recall@k. Для генерации считались полнота ключевых фактов и опора на контекст.

## Результаты

| Гипотеза | Что сравнивала | Результат |
|---|---|---|
| 1. Overlap | fixed-size 200 токенов, overlap 0 и 40 | Recall@5 0,70 → 0,75, но фрагментов на 23% больше; на q4 стало хуже |
| 2. Смысловые chunks | границы по падению сходства соседних предложений | Recall@1 0,25 → 0,47, но Recall@5 упал до 0,66 |
| 3. Dense, BM25, RRF | 5 смысловых и 5 точных запросов | Dense лучше на смысловых (Recall@5 0,90), BM25 — на точных (0,90); гибрид не выигрывает автоматически |
| 4. Top-k для генерации | k = 1, 3, 5, 10 | лучший k = 5: оценка 3,4 из 5 против 2,4 при k = 1; при k = 10 появляется шум |

Главный вывод: в RAG нельзя улучшать одну часть отдельно. Overlap меняет размер базы, chunking — форму контекста, retrieval — качество поиска, а top-k — объём текста для модели. Хороший поиск ещё не гарантирует хороший ответ: на вопросе q8 нужный фрагмент был найден, а модель всё равно не назвала ключевые цифры.

## Запуск

```bash
pip install -r requirements.txt
```

Тексты статей в репозиторий не включены. Для запуска положите корпус в папку `data_txt/` в виде файлов `doc_01.txt` … `doc_10.txt`.

## Ограничения

Корпус небольшой, поэтому один вопрос заметно сдвигает среднее. Релевантность размечена вручную. Автоматическая оценка ответов проверяет ключевые факты, но не заменяет экспертную. Qwen2.5-0.5B — компактная модель, и часть ошибок связана с генератором, а не с поиском.
